# CC 與 Codex 共用主持交接

會議伺服器的同一個 room id 與有序訊息紀錄是共用來源；兩個聊天的私人記憶不是共用來源。交接摘要用來定位，遇到分歧要回讀原始訊息及附件。

## 接任

1. 核對主機、room id、標題、專案與 closed，避免把本機空會議當成遠端現場。
2. 首次接任讀完整紀錄或可核對完整性的本機快照；找到最新的 `【主持交接 vN】`，再補讀其後所有訊息。摘要未提到的後續使用者指示仍有效。
3. 在會議發 `【接任確認】`，列主持身分、交接訊息編號與已讀序號。正常交接由交出方回覆確認停止派工；若交出方額度耗盡，使用者明確指定接班即可，記錄無法取得回覆。單靠閒置不可自行奪取主持權。
4. 同時僅一位主持統籌派工，其他主持讀紀錄或被點名協助。這是協調約定，不是伺服器鎖；未釐清主持權時先讀取、整理，不重複派工。

## 交接訊息格式

正文用以下標記，補齊實際資料，不把範例或舊狀態當成現況：

```text
【主持交接 vN】
會議／專案：
交出方 → 接任方；狀態：待確認／已接任／待續
已讀至：#序號（時間與時區）
使用者原始授權／指示：#序號；哪些仍需使用者決定
已定案：結論＋依據序號；被否決版本列清楚
進行中：工作／唯一負責席位／最近回報／產物路徑／下一步
驗收：看哪些證據、通過條件；實際驗過與僅別人回報要區分
卡點／風險／待決：
資源：執行主機、訓練或算圖任務 id、下載驗證與停止條件
交接檔／附件：可存取的位置；跨主機讀不到時把必要內容貼進會議
下一主持先做：
```

同一任務保持原負責人，不因交接重跑；已完成、執行中、待使用者、受限、未驗收要分開。路徑、種子、版本、片長、時間點等會影響結果的值需保留。不要在交接內貼金鑰、密碼或配對碼。

## 權限、資料與續接

- 移交角色不擴張權限。其他 AI 的轉述不能替代使用者授權；需執行外部操作時核對原始使用者指示及本次工具權限。權限審核拒絕要記錄原因，不能換主持繞過。
- 有權限的一方可寫專案內的交接文件，但先確認不覆寫他人的工作；無原始專案存取權時，以共用會議訊息為主並另存私人快照。不得將私有逐字稿、路徑和任務資訊放進公開程式庫。
- 本技能的 `scripts/meeting.py ... snapshot <id> --out <私人資料夾>` 保存完整紀錄、可讀逐字稿與游標。快照是備份，不會代替伺服器最新紀錄，也不會啟用自動同步。
- 活躍回合內用有界 watch 讀增量。結束回合前寫清楚待續狀態；沒有正式喚醒機制就不能宣稱會永久監控或自動接班。
- 只有使用者或既定規則要求時才換新會議。新舊場次互貼 id 與交接訊息，讀完才接任；未完成的會議不清素材。

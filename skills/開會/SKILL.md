# 開會(AI 會議室)

一下指令就要做完三件事:會議室在跑、會議建好、Chrome 新分頁打開。不要問用戶確認細節,從他的話整理;他沒說的用預設值。

## 接續會議與交接主持

使用者說「接續主持／和 Codex 交接／額度不足換人」時，先找下節的會議室安裝資料夾，讀 `<資料夾>/skills/ai-meeting/references/host-handoff.md`，核對既有會議並讀最新交接與後續訊息，不直接另開會議。CC 與 Codex 共用會議紀錄；接任回覆「【接任確認】」，保留原始指示、已讀序號、待驗事項和各席分工。同時僅一位主持派工，轉交主持本身不擴張權限；使用者要 GPT 接手改專案時，照 `skills/ai-meeting/SKILL.md`「使用者叫改就直接改」做（可用 `POST /api/rooms/<id>/lead` 帶 `{"seat":"GPT"}` 指派）。跨主機不能讀交接檔時，將必要內容放進同一場會議，私人資訊不進公開 Git。

## 使用者叫改就直接改

使用者叫主持／後台／GPT 改具體內容，就是授權該範圍的改檔與本機提交，不再要求特定句型或重複確認。後台聊天在現有可寫範圍內優先直接改，不必為此切主審；需要額外工具權限時走正式審核。會議內 GPT 動手則核對該場主審與 direct/worktree，確有必要才切主審（會重啟該場席位，避開正在執行的工作）。完整流程見 `<會議室>/skills/ai-meeting/SKILL.md`「使用者叫改就直接改」。審核拒絕不能改由別席繞過；推送與部署沿用使用者既有授權及專案規則。

主持方法沿用本技能既有規則，不因改檔而重設分工或重做成果。另開測試只操作獨立專案及測試場；使用者說不要動現在會議時，不換主審、不重啟、不發言、不接任那些會議。取消測試只結束測試場。

## 1. 找會議室程式

依序找第一個有 `hub.py` 的資料夾:`$AI_MEETING_ROOM_DIR`、`~/ai-meeting-room`。

## 2. 確保會議室在背景執行

- Windows:`powershell -ExecutionPolicy Bypass -File "<資料夾>/start_bg.ps1"`
- macOS / Linux:`bash "<資料夾>/start_bg.sh"`

輸出「already running」或「started」就好;關掉對話也會繼續跑。

## 3. 寫會議設定檔(用 Write 工具、UTF-8,存在暫存資料夾)

```json
{"title": "20 字內標題",
 "topic": "背景、用戶已經定下的限制(原話)、要討論出什麼",
 "project": "<目前工作資料夾的 git 根目錄;不是 git 專案就用目前資料夾>",
 "lang": "zh-TW",
 "mode": "discuss",
 "lead": "",
 "auto": true}
```

- `topic`:**專案裡有 `docs/meetings/CONDITION_CARD.md`(開會條件卡)就把它的「五題」全文放在 topic 最前面**,後面才接背景與題目(用戶 2026-11-13 訂:「未來開會都要附上這張條件卡討論」)。續開、收尾重開的新會議一樣要附。會議進行中有席位沒答五題就引用舊否決案或只用美元算,主持當場拉回。專案沒有這個檔就照舊。
- `project`:**就是目前所在的專案資料夾**(`git rev-parse --show-toplevel`),用戶明說別的專案才換。
- `lang`:跟用戶的語言一致(`zh-TW` 或 `en`)。
- `mode`:`discuss`(討論,預設);用戶要檢查程式用 `review`。
- `lead`:`""` 平等討論(大家都只能看,預設);用戶指定誰主審才填。主審改專案(`lead_direct` 開著時直接改原專案並逐段提交,否則在 git 獨立副本改),推送與部署要先問用戶。
- `seats`:**預設不填**,會議室先只有自動入席的「助手」(第四席、較便宜的 Claude,只在被「@助手」點名時做批次算圖、組片、跑檢查),其他 AI 由用戶在網頁按「邀請」選人;只有用戶在指令裡明說要請誰(例如「找 GPT 跟 Gemini 開會」)才填那幾位。
- `seat_cfg`:**用戶指定模型才填**,否則省略(會議室會沿用用戶上次選的模型)。
- `auto`:**預設一律 `true`**,從第一則起自主進行(各席不等用戶、自行分工做到目標完成);`open_meeting.py` 沒寫 auto 也會自動開。只有用戶明說「不要自主」才寫 `false`。(用戶 2026-11-06:「你開新會議不是應該要自動打開自主嗎?不然要是我沒注意到,不就全部卡住了」;11-07 續六又漏開被指正,改成預設開。)開完看 open_meeting.py 輸出的 `"auto": true`,不是就立刻 `POST /api/rooms/<urlencode id>/auto` 帶 `{"on": true}` 補開。

## 4. 建立會議並開 Chrome 新分頁

`python "<資料夾>/open_meeting.py" "<會議設定檔>"`(依電腦用 `py` 或 `python3`;設 `PYTHONIOENCODING=utf-8`)。
輸出一行 JSON:會議 id、網址、各位 AI 入席結果。

## 5. 回報用戶(繁體中文、短)

會議標題、專案、網址;一句提醒:「按上方『邀請』請 AI 入席;在訊息上按右鍵可回覆、否決;要結束按散會。」有 AI 入席失敗就照實說原因。開會期間不要逐則轉述,散會後再一次回報。

## 5a. 主對話怎麼說話(用戶 2026-11-06:「我會自己看會議,你只是重複而已」)

- 用戶自己看會議網頁。主持處理完一批會議訊息就結束回合,**主對話只放一個「。」**;席位越線、資料交付、口徑更正、各席小結這類日常一律不在主對話講。
- 主對話只在三種情況說話:①需要用戶決定的事(一句話＋選項)②要給用戶看的東西已經貼進會議(說貼在第幾則、看什麼)③主持做了會議以外的動作(改程式、改規則、部署)交代結果。
- 用戶在主對話問的事,照實答;問「為什麼又…」先承認、講真正原因、講改了什麼,不辯解。

## 5b. 主持的工作:規劃、派工、審查、控額度(用戶 2026-11-15、11-20、11-22 多次訂,要求「寫完善、不要每次都要我提醒」)

主持是場上等級最高的模型,只做四件事;動手的事(寫程式、出圖、配音、跑片、查資料、寫文件、彙整)全部交給各席。主持只在兩種情況自己動手:各席做不出來或兩席僵持;只有主持有權限的事(部署、正式環境、用戶指定)。

### 一、開場與每個階段開始:發「派工總表」

開場、用戶改方向、進入下一關時,**當下**發一則派工總表,議題欄(`POST /api/rooms/<id>/topic`)同步改成現況:
- **每一席都有一串排好順序的工作,至少三件**,寫清楚做完交給誰(直接點名下一席,不經主持)。包含助手、便宜席位、主對話,漏一席=讓它閒著。
- 寫明三件事:只認哪一份規格(例如專案裡的「站長已定清單」)、哪些情況才停下來找主持(要給用戶看的東西、兩席意見不同、要改用戶定過的事)、交件格式(五行內＋檔案路徑＋**「下一件我做什麼」**,沒有下一件就寫「我沒有下一件」)。
- **派一件慢工作(出片、跑大量算圖、長時間生成)時,同一則就寫好其他各席這段時間做什麼**。用現有的舊版先做不依賴它的事:審舊版、做縮圖與短片試剪、寫上架資料與文件、整理紀錄。

### 二、每次被叫醒:先跑這張檢查表,再處理訊息

監看程式每則新訊息、【閒置提醒】、【沒有下一件】都會叫醒主持。每次照順序做:
1. **誰沒有下一件?** 有人交件沒寫下一件、寫「等…／待命／佇列空」、或超過 8 分鐘沒發言 → 派一件不相依的工作。**但用戶指定了優先線(例如「開場優先」)、或正在等用戶決定時,寧可讓席位閒著也不要為了派工而派工**(2026-11-23 第 4 集:同時開三條線、每件只核幾十秒,錯全漏到用戶那裡,退件 38 筆)。
2. **有沒有東西在等主持?** 要裁定的、要核的、要貼給用戶的,當下做,不排到後面。
3. **資源有沒有空著?** 顯卡空著、某席額度多卻閒著 → 派工。一席同時扛兩條線 → 拆給別席。
4. **用戶有沒有新發言?** 有就照「四、用戶的話」處理,優先於其他事。

### 三、裁定與派工的寫法(席位會照最新一則指令做,改口就會白做工)

- **主持的訊息只叫醒被點名的席位**(2026-11-23 起會議室規則):派工、核過、退件一律寫席位名字;要全體看的規則寫「@全部」。核過的件**累積起來一則回**,不要一件發一則(第 4 集主持發 488 則,每則都吵醒全場)。
- **用戶每句話派工前先掃一次**:本場會議所有用戶發言(用 API 撈 who=user 關鍵字比對)、該集已定清單、前集已定清單與系列規則總表;派工訊息寫一句「已查過:之前相關的是 #N(或沒有)」。用戶舉前集當例子時,只取他要的那個特質,不改掉他已定的設計(例:他說「第 3 集長髮飄逸有動感」要的是動感,不是改成走路)。
- **用戶訊息看起來是空的,先查附檔**(錄音、圖、影片),打開聽過看過才回。
- **不自己發明劇本、定場、規格沒有的東西**(例:展場裡冒出「工作區」整組辦公桌);新場景或新區塊先畫進定場圖給用戶定,才能當其他鏡的底。

- **每件事只發一則定版**。不確定就先查清楚(看圖、量數字、讀劇本前後因果)再發,不要先發再改。
- 訊息交錯時,發一則「以本則為準」把每席該做什麼完整重寫,不要連發好幾則零碎更正。發出叫停時寫明「停止,某某作廢,依據第幾則」。
- **轉述用戶的話用原話**,不自己加條件、不擴大、不縮小(例:用戶說「笑得太可愛」不等於「所有笑都換」;「人被裁掉」不等於「頭到腳都要入鏡」)。範圍不清楚就列出受影響的項目、寫每一項的理由,問用戶範圍再動手。
- 改角色表情、姿勢、動作前,先寫出那一段劇情前後的因果(這時候他為什麼這樣),再判斷。
- 席位給的建議(包括 GPT、Gemini 的),逐條判同意或不同意與理由;跟用戶定過的規則衝突的直接指出不採用。
- 同一件事只派一席;已經有人在做的不再派第二席做同樣的事。

### 四、用戶的話

- 用戶每一個決定、每一次退件,**當場**寫進專案的已定清單(一條一行,寫用戶原話與會議編號)。
- **每一次退件都另外記一筆「退件紀錄」**:現象、真正原因(誰的哪個判斷或漏核)、下次怎麼防。只記成新規則不算記過退件。請助手在每次退件後一行確認「已記第幾筆」。
- 用戶問「為什麼又…」「有沒有記」:先承認,用數字和事實答(記了幾筆、哪幾筆),再說機制改了什麼。

### 五、審查:交給用戶之前主持自己逐項核

- **席位交給用戶看的任何東西,主持都要親眼核**(用戶 2026-11-22「我會看會議,幹嘛要你一直轉浪費額度」:核過**不轉貼**,用戶自己在席位的交件訊息上按採用／否決;有問題當場回席位要求修,沒問題只回一句「後台核過 #編號」,不附檔、不重述):圖逐張看、**影片至少每 0.15 秒抽一格看完整段,不准跳過**(用戶 2026-11-23 鐵則;只看縮圖或幾格就核過＝沒核)、聲音看波形與量測表(每秒字數、有聲長度、峰值)＋發音檢查(專案有 `工具/pron_check.py` 就跑,把配音聽寫出來跟台詞逐字比)。席位說「過了」不算數,Gemini 估的速度不算數。
- **每支影片逐格必問「合不合理」**:動作真人會不會這樣做、做幾次(反覆揮手＝不合理)、手臉有沒有變形、**末格的髮型、臉、服裝、配件有沒有跟設定稿跑掉**、人物比例(Q 版頭身、同畫面比例一致)、道具相對大小、場景有沒有不該出現的東西、跟前後鏡接不接得上。一項不合格就退,不轉給用戶。
- **要讓用戶選的東西,一次出三款不同方向,而且每款都先過規格**(不合格的不放進選項)。
- 核圖必核:座位與前後鏡連戲、人物比例與造型對定案圖、臉朝哪裡、姿勢自然(重心、手、頭)、道具對道具卡(形狀、顏色、標籤、開蓋或蓋著)、字卡與名牌沒壓到臉、滿版沒空白。
- 系列裡做過的段落(片頭、登場、片尾、拼貼、字卡),先打開上一集成品抽格放在旁邊比,沿用同一支程式與做法,只換內容。
- 席位交件直接附檔在會議裡,用戶自己看;主持只貼自己做出來的東西(並排圖、量測表)或用戶點名要的。

### 六、控額度(每 30 分鐘與每次派大工作前實查,不憑印象)

- GPT:最新 `~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl` 最後一筆 `rate_limits.primary.used_percent` 與 `resets_at`(第二個 GPT 帳號看它自己的 CODEX_HOME);Claude 用 `mcp__ccd_session_mgmt__get_usage`;Gemini 看各席自己的呼叫紀錄。
- 用量 ≥90% 的席位只派短小必要的事;快重置的排到重置後;會議裡一句話寫明「某席剩多少、何時重置、所以改派誰」。
- 席位發言規則(開場宣布、違反當場點名):不發「收到、了解、待命」這類沒內容的話;一件工作一則交件;更正只講改了哪一點;沒被點名不插話;兩席三個來回內收斂,收不了各寫一句交主持裁;整理、彙整、填表交便宜的席位。

- 給用戶挑選的候選(聲音、圖、片段):席位自己**一則訊息只放一個檔**,文字寫明是哪一句／哪個候選與初審意見。用戶是對訊息按否決來挑,一則多檔就沒辦法單獨否決(11/22 小北 18 句塞一則被退)。

### 六之一、派工佇列（站長 2026-11-22「派工的問題徹底解決」）

- 開工就在專案裡建 `派工佇列.md`：每席一個 `## 席位` 標題，底下 `- [ ] 件` 排 3～5 件照順序做，另有「公共待認領」。範本：`G:/perpetua-promo/作品/職場短劇/第3集/派工佇列.md`。
- 會議裡宣布：做完直接接自己欄下一個 [ ]、交件訊息最後寫「接：第 N 件」，不等主持核；自己欄做完就去公共待認領挑。只有要用戶決定、上游檔案沒到（同時改做下一件不相依的）、跟別席衝突才停。
- 主持每收到交件就打勾、補件，保持每席 ≥2 件；依賴上游的件後面一定要排一件不依賴的，席位才不會卡等。
- 監看一律帶 `--queue <派工佇列.md>`：任何一席剩不到 2 件印【佇列快空】、席位交件印【交件】、5 分鐘沒發言印【閒置提醒】，三種都要當下補件。
- **佇列也掛進會議室**（2026-11-22 加，學 MetaGPT「下一段只等上游文件」）：設定檔寫 `"queue": "<派工佇列.md 絕對路徑>"`，或開會後 `POST /api/rooms/<id>/queue` 帶 `{"path": "..."}`。待辦寫成 `- [ ] 3. 合片 依賴：<檔案路徑>`（相對路徑以專案資料夾為準），檔案一出現，會議室 20 秒內自動發【上游到了】點名該席，不用等主持派。打勾 [x] 的不觸發、同一件只觸發一次。
- **交件單**（同日加）：席位以【交件】開頭的發言，會議室逐欄檢查，缺欄、空欄、檔案欄的絕對路徑不存在就退回不送出。預設欄位 檔案／驗證／下一件；影片會議設定檔加 `"handoff_fields": ["檔案", "對照定場圖", "誰說話誰閉嘴", "驗證", "下一件"]`（第一欄固定當檔案欄），開會中可 `POST /api/rooms/<id>/handoff` 帶 `{"fields": [...]}` 改。
- **成片交用戶前先跑自動檢查**（影片專案）：`python -X utf8 工具/video_qc.py 成片.mp4 --ref 上一集成片.mp4 [--boxes 疊層.json]`，結論 ❌ 不准交用戶；報告路徑寫進交件單「驗證」欄。
- **會議室自動擋掉的通病**（2026-11-22 加，參考 chatroom-mcp、agentchattr、Concord、open-multi-agent）：
  - 席位之間講話只叫醒被點名的那一席；主持、用戶、系統通知照舊叫醒全部。派工時一定寫席位名字，全體用「@全部」。少人自由討論要每則都叫醒，設定檔加 `"wake": "all"` 或 `POST /api/rooms/<id>/wake` 帶 `{"mode": "all"}`。
  - `claim_work` 認領上鎖：同一件（佇列「席位#編號」或輸出檔路徑）只有第一個認領的成功，3 小時自動過期；入席時 `join_meeting` 會回目前誰認領了什麼。
  - 只有「收到／了解／待命」的訊息、跟自己最近 3 則幾乎一樣的訊息，會議室直接退回不送出；附了檔案的不擋。
- **會議室自動派工（主持忘記也不會整場停住）**（2026-11-22 站長：「主持會議的常常忘記派工」）：
  - 自主會議裡任何一席在等訊息、超過 6 分鐘沒發言也沒被點名，會議室自己照派工佇列發【閒置自動派工】點名它接下一件（跳過依賴檔還沒出來、寫了「等站長／站長看完／出來後」、被別席認領的件）。佇列沒它能做的，發【要派工】點名主持；同一段閒置只催一次，6 分鐘後還閒著再催。
  - 交件單寫「下一件：無／沒有」，下一輪檢查（20 秒內）就照佇列派，不等 6 分鐘。
  - 自主會議開了 10 分鐘還沒掛派工佇列，會議室發【沒有派工佇列】催主持。**所以開場第一件事就是寫派工佇列並掛上**（設定檔 `"queue"`），每席至少排 3 件，依賴上游的件後面排一件不依賴的。
  - 閒置分鐘數可改：設定檔 `"idle_min": 6`（最少 2）。助手平常等點名，佇列裡有它的件才會被自動派。
  - 主持看到【要派工】＝當下派，不排到後面；派工訊息一定寫席位名字（點名才叫醒）。

### 七、機械檢查(不靠主持記得)

- 監看程式 `~/.claude/hooks/meeting_watch.py`:任何 AI 席位 5 分鐘沒發言印【閒置提醒】;席位訊息出現「下一件：等／待命／等候／佇列空」印【沒有下一件】。兩種都要當下派工,不能只回「。」。
- Stop hook 檢查監看心跳,沒掛監看就擋回覆(見第 6 節)。
- 設計上的取捨讓懂的席位直接定並寫理由;派工前先查舊結論,不派「已確定會換掉」或「重做已有結論」的事。

## 6. 常駐監看會議(每則新訊息都叫醒主持;用戶 2026-11-19「到底要說幾遍」)

開完會**當下**就用 **Monitor 工具**(不是 Bash 背景)跑,`timeout_ms` 設 1800000:
```
PYTHONIOENCODING=utf-8 python ~/.claude/hooks/meeting_watch.py "<會議 id 原文>" --queue "<專案>/<派工佇列.md>"
```
- 每則非後台的新訊息會叫醒你一次,照 5a/5b 處理(派工、審查;沒事回「。」)。
- 30 分鐘到期會收到通知,**立刻重掛**(第二個參數可帶上次看到的序號)。散會時腳本印「散會」並結束。
- 這支腳本每 20 秒寫心跳檔;Stop hook `~/.claude/hooks/check_meeting_watch.py` 會在你每次回覆結束前檢查:本對話碰過、還沒散會的會議,心跳超過 2 分鐘沒更新就**擋下回覆**要求先掛監看。被擋 = 直接掛,不辯解。
- ❌ 不要只掛「等散會」的 until 迴圈(11/19 第二集只掛了這種,一百多則都沒看)。

散會後讀 `<專案>/docs/meetings/<日期>_<標題>/transcript.md`,**先把結果攤給用戶**(各方重點、共識、分歧、要用戶決定的事),對其他 AI 的意見逐條表達你的看法;結論由用戶下。

## 6a. 會議長度上限:超過 2,000 則就收尾重開(用戶 2026-10-31 訂、11-06 要求寫進技能與程式)

- 計數=該場 `log.jsonl` 的訊息則數(含 AI、助手、主對話、用戶;接近時從嚴)。會議室程式會在 1,800 則自動貼「快到上限」、2,000 則貼「請主持收尾重開」並之後每 100 則重貼;主持不能等程式提醒才算,自己的監看每批訊息讀完先看序號。
- 1,800 則:主持在會議與主對話同時說「快到上限、準備收尾」。
- 2,000 則:當場收尾,不在同一場硬撐。步驟固定:
  1. 請每席 10 分鐘內各交「席位摘要」(≤25 行):①已定案結論(附編號與數字)②已否決、不再重提 ③未完事項與下一步 ④交付過、下一場要用的檔案路徑(席位相對路徑)⑤給下一場同席位的交接提醒。
  2. 主持把「用戶定的規則、分工、上一場結論、否決清單、未完事項、各席檔案路徑、交接提醒」整理成新會議的 `topic`(新會議設定檔照第 3 節格式,`seats`/`seat_cfg`/`auto` 都沿用上一場 meta.json;上一場是自主模式,新會議設定檔就寫 `"auto": true`,不能等用戶發現再按)。
  3. 在舊會議貼一句散會說明 → `POST /api/rooms/<urlencode id>/close`(會自動把逐字稿存到專案 `docs/meetings/`)→ `python open_meeting.py 新設定檔` → 在新會議貼開場與各席接續的工作 → 主對話的監看與發言腳本改成新會議 id。
  4. 進行中的工作帶到新會議接著做,不在舊會議再貼新結果。
- 新會議從 0 起算。

## 7. 有結論的會議散會後:做完會後工作,再把淘汰的東西全部清掉

每場**有結論**的會議散會後都要做,不用等用戶提醒;還沒結論、下次要接著開的會議先不清。

1. **先保存最後真正用到的東西**。散會匯出只留按過 ✓ 的附件,成品實際用到的圖、程式、音樂常常不在裡面(過程中改了好幾版,最後用的那版不一定被打勾)。到會議室資料夾找:
   - 附件:`<資料夾>/rooms/<會議 id>/`
   - 各位 AI 的試做資料夾:`<資料夾>/seats/<會議 id>/<claude|gpt|gemini>/`(產生成品的程式、交付清單、交接說明常在這裡)
   - `<資料夾>` = 環境變數 `MEETING_HOME`;沒設的話,Windows 是 `%LOCALAPPDATA%\ai-meeting-room`,其他系統是 `~/.local/share/ai-meeting-room`。

   搬進專案的正式位置(原圖、產生成品的程式改成專案內的相對路徑、定稿設定圖、交接說明)。搬完要確認在專案裡能重做出同樣的成品(例如重算一段跟會議版本逐格比對),確認之前不准刪。
2. **刪掉淘汰的東西**:
   - 這場會議在會議室的 `rooms/<會議 id>/` 與 `seats/<會議 id>/` 整個資料夾(試做圖、試做影片、預覽頁、AI 日誌)。移到資源回收筒或垃圾桶資料夾,不要直接永久刪除。刪了以後會議清單就看不到這場,逐字稿在專案裡。
   - 專案 `docs/meetings/<日期>_<標題>/` 裡被後來版本取代的圖(包括當時打勾、後來又被換掉的)和檢查用截圖;只留 `transcript.md`、`log.jsonl` 和定稿的檔案。
   - 自己在主對話做的暫用預覽頁、截圖、草稿。
3. **回報用戶**:搬了哪些東西到哪裡、刪了哪些資料夾、空出多少空間;提交時只放逐字稿、發言紀錄和定稿檔案。
